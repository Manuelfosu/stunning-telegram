# Render deployment

## Recommended: Blueprint

1. Push the complete repository to GitHub or GitLab.
2. In Render choose **New → Blueprint** and select the repository.
3. Render reads `render.yaml`, asks for `ADMIN_PASSWORD`, generates `SECRET_KEY`, builds the Docker image, and starts one web service.
4. Open `/api/health`; it must return `{"status":"ok"}`.
5. Open the service URL and sign in using the admin phone configured in Render.
6. Change the bootstrap password immediately.

The Docker image compiles React in a Node build stage and copies `dist` into the FastAPI runtime. The UI, API, uploads and WebSocket therefore share one origin.

## Persistence warning

Render Free has ephemeral storage. For real users, use a persistent disk or PostgreSQL. With a disk mounted at `/var/data`, set:

- `DATABASE_URL=sqlite:////var/data/ssga.db`
- `UPLOAD_DIR=/var/data/uploads`

## Required environment variables

- `SECRET_KEY`: generated by the Blueprint.
- `ADMIN_PASSWORD`: set a strong first-run password.
- `ADMIN_PHONE`: bootstrap admin phone.
- `ALLOWED_ORIGINS`: `*` is valid for the single-origin Docker deployment.
- `PORT`: supplied automatically by Render.

## Pre-deploy commands

```bash
cd frontend
npm install
npm run typecheck
npm run build

cd ../backend
python -m py_compile app/*.py app/routers/*.py
```

`npm run build` uses Vite's production compiler. `npm run typecheck` remains a
separate development/CI quality check so a type-only diagnostic cannot prevent
Render from producing the already bundle-validated application.

## Operational checks

- Registration requires full name, phone, password confirmation and CAPTCHA.
- A deposit is created only after **I HAVE PAID**.
- Admin approval credits deposit balance exactly once.
- Withdrawals debit earnings immediately; rejection refunds exactly once.
- Completing five daily questions unlocks and automatically credits eligible package income.
- Admin WebSocket alerts arrive for new deposits and withdrawals.
- `/api/admin/logs` records sensitive admin operations.
